# 04. 구현 순서와 데모 완료 기준

## 1. 작은 단위로 구현

| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | Expo 앱과 준비 화면 | Android Expo Go에서 열림 |
| 2 | 가속도 구독·진동 시험 | 실제 값·진동 확인 |
| 3 | 3초 준비 +35초 시간표 | 안내·진동·중단 연결 |
| 4 | RMS·기준 비율 계산 | 원본에서 실제 값 생성 |
| 5 | 선 그래프·결과표 | 구간과 값이 함께 보임 |
| 6 | JSON 저장·공유 | 공유한 파일을 읽을 수 있음 |

첫 구현은 엄지–검지 한 자세, 가속도계 한 개, 화면 세 상태로 완성합니다. 결과가 확보된 뒤 자이로·고속 분석·다른 자세를 추가합니다.

## 2. 필요한 자동 테스트

계산 함수와 시간표에 집중합니다. 정해진 값을 확인하는 UI 스냅샷 테스트를 많이 만들 필요는 없습니다.

| 테스트 | 기대 결과 |
|---|---|
| 일정한 중력 벡터 | 창별 평균 제거 후 RMS≈0 |
| 일정한 진폭의 충분한 주기 정현파 | RMS≈진폭/√2 |
| 신호 진폭 2배 | RMS도 약 2배 |
| 기준 대비 1.2배 | 비율 1.2 유지 |
| NaN·빈 창·0 기준 | 유효 숫자로 위장하지 않고 `null` |
| 센서 표본의 큰 간격 | 해당 창·구간 품질 표시 |
| 수신 이벤트 몰림 | 시간 범위·지터 검사가 해당 창을 무효 처리 |
| 35초 시간표 | 각 경계·진동 3–33초 일치 |
| 시작 연타·중단 | 구독·진동·타이머 중복 없음 |
| JSON 재계산 | 원본으로 계산한 결과가 저장 결과와 수치 오차 범위에서 일치 |

정현파는 요청 100 Hz에서 충분히 관찰 가능한 10 Hz 같은 테스트 주파수를 사용합니다. 이것은 구현 검증용 합성 신호입니다. 휴대폰 모터의 주파수라고 표시하지 않습니다.

## 3. 실기기 시연

| 단계 | 확인할 것 |
|---|---|
| 준비 | 책상 위 접점, 케이스 상태, Android 기기 |
| 시작 | 카운트다운 동안 자세를 잡을 수 있음 |
| 기록 | 진동이 켜지고 안내에 따라 집기·완화 가능 |
| 표시 | 그래프가 실제 센서 기록을 반영 |
| 종료 | 진동이 멈추고 결과가 표시 |
| 공유 | 같은 세션의 JSON 파일 공유 |
| 중단 | 중단·배경 이동 때 진동 정지와 구독 해제 |

신호 변화가 작거나 방향이 일정하지 않아도 실제 값을 유지합니다. **앱 동작 완료**와 **집기 변화가 센서에 뚜렷하게 나타나는지**는 따로 보고합니다.

## 4. 제출할 것

1. 실행 가능한 Expo 프로젝트와 lockfile.
2. 설치·실행 명령이 담긴 앱 README.
3. 사용한 Expo SDK와 실제 시험 환경.
4. 자동 테스트·타입 검사 결과.
5. 실기기 시험을 했다면 해당 JSON과 결과 화면.
6. 조정한 설정과 실제로 남은 확인 사항.

Expo Go로 실행할 수 있으면 APK 생성은 필수 제출물로 요구하지 않습니다. 개발 빌드가 필요해진 경우에만 해당 이유와 빌드 방법을 추가합니다.

실기기를 사용할 수 없으면 수행한 빌드·타입 검사·계산 테스트까지만 완료로 보고합니다. 재생 데이터 화면은 `예시 재생` 표시를 유지합니다.

## 5. 첫 데모의 범위선

| 지금 구현 | 다음 단계 |
|---|---|
| 앱 내부 계산·JSON 공유 | 서버·DB·회원 기능 |
| RMS 상대 변화 | 기준 힘으로 학습한 kgf 추정 |
| Android 실측 | iOS의 별도 진동 프로토콜 |
| 엄지–검지 한 자세 | 나머지 네 자세 |
| 간단한 시간 영역 분석 | 고속 센서·주파수 대역 분석 |

코딩 과정에서 문제가 생기면 원본을 확인하고 작은 범위에서 수정합니다. 가짜 값이나 임의 환산식을 넣어 데모를 성공처럼 보이게 만들지 않습니다.
