# 07. 센서 측정에서 집게힘 숫자까지 — 구현 보완 명세

**이 문서가 이번 요청의 핵심입니다.**  
목표: 현재 아이폰 앱에서 측정한 센서 특징을 임시 모델에 넣어 **kgf 숫자가 나오는 데모**를 완성합니다.

## 1. 논문의 방식은 어떤 계산인가

논문의 절대 힘 모델은 처리한 센서 특징을 표준화하고 Ridge 회귀에 넣는 구조입니다. 구체적인 논문 처리 조건과 계수 확인 범위는 [05](05_APPENDIX_AND_REFERENCES.md)에 정리했습니다.

일반적인 선형 회귀의 예측 단계는 아래처럼 쓸 수 있습니다.[^ridge][^scaler]

\[
z_j=\frac{x_j-\mu_j}{s_j}
\]
\[
\hat F=b+\sum_{j=1}^{p}w_jz_j
\]

| 기호 | 구현에서 하는 일 |
|---|---|
| `x_j` | 센서에서 계산한 특징을 입력 |
| `μ_j, s_j` | 특징을 모델이 기대하는 크기로 변환 |
| `w_j` | 각 특징의 가중치 |
| `b` | 절편 |
| `F` | 모델이 출력하는 힘 |

학습은 `μ, s, w, b`를 데이터로 정하는 과정입니다. **예측할 때는 저장된 값으로 빼기·나누기·곱하기·더하기를 수행합니다.** 따라서 Expo 앱 안에서도 계산할 수 있습니다.

이번 데모에서는 이 값들을 임의로 지정합니다. 모델 파일의 `training_status=placeholder`가 이를 나타냅니다. 논문의 절대 힘 출력은 lb 단위이지만, 우리 임시 모델은 처음부터 kgf 단위로 정의합니다. 추후 lb 출력 모델을 사용할 때만 `kgf=lb×0.45359237` 변환을 적용합니다.

## 2. 현재 앱에서 무엇을 입력할 것인가

입력은 이미 계산 중인 **가속도 RMS 비율 한 개**입니다.

\[
r=\frac{\text{현재 창의 RMS}}{\text{최초 가벼운 접촉 구간의 기준 RMS}}
\]

- 실시간 계산: `features[i].ratio`를 사용합니다.
- 반복별 결과: `summary.trials[i].pinch_ratio`를 사용합니다.
- `median_trial_delta`, 관측 속도, 변동계수는 모델 입력으로 사용하지 않습니다.
- 가속도 원본 g 값을 모델에 바로 넣지 않습니다.
- 기준 RMS는 세션 최초 기준으로 고정합니다. 각 반복에서 다시 1로 맞추지 않습니다.

기존 앱이 이 특징까지 계산하므로 센서 수집부를 새로 만들 필요는 없습니다.

## 3. 임시 값은 이렇게 정한다

| 설정 | 기본값 | 뜻 |
|---|---:|---|
| 특징 수 | 1 | `accel_rms_ratio` |
| 평균 `μ` | 1.0 | 기준 비율 1을 중심으로 계산 |
| 스케일 `s` | 1.0 | 비율을 그대로 사용 |
| 가중치 `w` | 5.0 | 비율이 1 증가할 때 데모 출력 5 kgf 증가 |
| 절편 `b` | 1.0 | 기준 비율 1일 때 데모 출력 1 kgf |
| 하한·상한 | 0.0 / 15.0 kgf | 화면용 출력 범위 |

1 kgf와 5 kgf, 15 kgf는 시연용 숫자입니다. **실제 기준 힘이나 사람의 정상 범위를 의미하지 않습니다.**

따라서 기본식은 다음처럼 단순해집니다.

\[
F_{\rm raw}=1+5(r-1)
\]
\[
F_{\rm demo}=\min(15,\max(0,F_{\rm raw}))
\]

예를 들어 `r=1.6`이면:

| 순서 | 계산 |
|---|---|
| 1. 중심값 빼기 | `1.6−1.0=0.6` |
| 2. 스케일로 나누기 | `0.6÷1.0=0.6` |
| 3. 가중치 곱하기 | `0.6×5=3.0` |
| 4. 절편 더하기 | `3.0+1.0=4.0` |
| 5. 범위 처리 | `0–15` 안이므로 그대로 |
| 6. 화면 | **집게힘 · 데모값 4.0 kgf** |

여기서 비율을 kgf로 연결하는 역할이 가중치와 절편입니다. 가속도 단위에 고정 환산 상수를 곱해 실제 힘이 자동으로 나오는 구조가 아닙니다.

## 4. 모델 설정 파일

다음 객체를 `demoForceModel.ts` 또는 JSON 설정에 둡니다. 측정 시작 시 복사하여 세션에 고정합니다.

~~~json
{
  "model_id": "demo_ac_ratio_linear_v1",
  "kind": "demo",
  "training_status": "placeholder",
  "feature_schema_id": "accel_rms_ratio_v1",
  "compatible_protocols": [
    "expo_desk_pinch_ios_pulsed_v1"
  ],
  "feature_order": [
    "accel_rms_ratio"
  ],
  "mean": [1.0],
  "scale": [1.0],
  "coefficients": [5.0],
  "intercept": 1.0,
  "output_unit": "kgf",
  "output_min": 0.0,
  "output_max": 15.0
}
~~~

### 모델 설정을 검증할 것

특징 이름·순서·벡터 길이가 일치해야 합니다. `mean/scale/coefficients`의 길이가 다르거나 `scale≤0`, 비유한수, 하한>상한이면 모델을 로드하지 않습니다.

특징이 빠졌다면 0으로 채우지 않습니다. 모델 ID·버전은 계수가 바뀌면 함께 바꿉니다. 임시 계수를 세션마다 자동 재조정하거나 가장 큰 입력에 맞춰 매번 15 kgf가 나오게 만들지 않습니다.

## 5. 추론 함수의 처리 순서

`predictForce(features, model)`는 다음 순서로 동작합니다.

1. 모델이 현재 특징 스키마와 호환되는지 검사합니다.
2. `feature_order` 순서대로 입력 벡터를 만듭니다.
3. 필요한 특징이 없거나 무효이면 값 `null`과 이유를 반환합니다.
4. 각 특징에서 `mean`을 빼고 `scale`로 나눕니다.
5. 표준화한 특징과 `coefficients`의 곱을 더합니다.
6. `intercept`를 더해 `raw_kgf`를 만듭니다.
7. 0–15 범위로 처리해 `value_kgf`를 만듭니다.
8. 모델 ID·`kind=demo`·범위 처리 여부를 함께 반환합니다.

이는 예측 함수 명세입니다. 앱 실행 중 모델 학습이나 외부 API 호출은 필요하지 않습니다.

반환 형식 예시:

~~~json
{
  "value_kgf": 4.0,
  "raw_kgf": 4.0,
  "kind": "demo",
  "model_id": "demo_ac_ratio_linear_v1",
  "clamped": false,
  "valid": true,
  "reasons": []
}
~~~

무효 입력에서는 `value_kgf`와 `raw_kgf`를 `null`로 두고 `valid=false` 및 이유를 남깁니다. **유효한 0 kgf와 값이 없는 상태를 구별**합니다.

## 6. 실시간 값과 최종값

### 실시간

유효한 500 ms 특징 창마다 같은 모델로 힘을 계산합니다. UI는 기존 100 ms 갱신 주기를 유지합니다. 계산 후 반올림은 표시 단계에서만 수행합니다.

측정 초기 기준 수집, 진동 꺼짐, 구간 전이, 무효 창에는 값을 표시하지 않습니다. 원본 특징이 없는데 단계 안내만 보고 고정 숫자를 출력하지 않습니다.

### 반복별 결과

`pinch_j` 시작 후 첫 1초를 제외한 유효 창들의 `r` 중앙값을 `R_j`라 합니다.

\[
F_j=\operatorname{predictForce}(R_j,\theta_{\rm demo})
\]

같은 모델을 세 반복에 적용합니다. 기존의 `Δ_j=R_j−L_j`는 상세 관찰값으로 남기고, 임시 힘 모델의 입력으로 쓰지 않습니다.

힘 결과에 필요한 것은 **해당 집기 구간의 유효 R_j와 최초 기준 B**입니다. 직전 완화 구간만 무효라면 Δ 비교는 무효로 두되, 집기 구간이 유효한 데모 힘은 계산할 수 있습니다. 두 유효성 필드를 분리합니다.

### 최종 대표값

\[
F_{\rm session}=\operatorname{median}(F_1,F_2,F_3)
\]

세 반복 모두 유효할 때 계산합니다. 기록 중단·필수 구간 부재 시 개별 결과를 보존하고 대표값은 비워 둡니다. 최대값·순간 피크를 대표값으로 바꾸지 않습니다.

## 7. 실제 공유 JSON에 적용하면

대상 기록: `pinch_20261118T035925274Z_le1zl-0dn72y.json`. 이 파일의 센서값은 실측이며, 아래 힘은 **그 특징에 이번 임시 계수를 사후 적용한 데모 계산값**입니다.

| 반복 | 기존 pinch_ratio | 계산 | 데모 출력 |
|---|---:|---|---:|
| 1 | 1.5524433593 | `1+5×(1.5524433593−1)` | **3.8 kgf** |
| 2 | 2.4464710269 | `1+5×(2.4464710269−1)` | **8.2 kgf** |
| 3 | 1.6229344557 | `1+5×(1.6229344557−1)` | **4.1 kgf** |

정렬하면 `3.7622, 4.1147, 8.2324`이므로 대표값은 **4.1 kgf**입니다.

이 결과가 “이 사용자의 실제 집게힘은 4.1 kgf”라는 검증을 의미하지는 않습니다. 임시 모델을 적용한 데모가 어떤 숫자를 출력해야 하는지 확인하는 예시입니다.

## 8. UI와 품질 처리

| 상황 | 화면·처리 |
|---|---|
| 정상 입력 | `집게힘 · 데모값 4.1 kgf` |
| 약한 진동 반응 메모 | 데모 계산 수행, 메모는 상세에 보존 |
| 불안정 기준 메모 | 계산 가능한 기준이면 데모 계산 수행, 상세 표시 |
| 기준 부재·비유한 입력 | `—`, 재측정 안내 |
| 출력 범위 초과 | 0 또는 15 표시, 상세에 `clamped=true` |
| 직접 입력 시험 | `입력값 시험` 표시 |
| 기존 기록 재계산 | `기록 재생 · 데모값` 표시 |

결과에 건강 판정·정상 범위·확률형 신뢰도를 추가하지 않습니다. 검증되지 않은 모델의 출처를 작은 `데모값` 표시로 명확히 하고 설명은 부록·상세에 둡니다.

## 9. 저장 계약

상위에 모델 전체를 `force_model`로 저장하고 각 특징에 `force_estimate`를 추가합니다. 반복 결과에도 `force_estimate`를 넣습니다. 최종 대표값은 `summary.force_estimate`입니다.

최종 결과 예시:

~~~json
{
  "schema_version": "2.0",
  "summary": {
    "force_estimate": {
      "value_kgf": 4.114672278298567,
      "kind": "demo",
      "model_id": "demo_ac_ratio_linear_v1",
      "aggregation": "median_of_three_trial_estimates",
      "valid": true,
      "reasons": []
    }
  }
}
~~~

기존 `summary.pinch_force_kgf=null`을 무조건 화면에 연결하던 코드는 새 `summary.force_estimate.value_kgf`로 전환합니다. v1 파일을 읽을 때에는 원본을 덮어쓰지 않고, 별도의 데모 재계산 결과를 만듭니다.

`data_origin=live`는 입력 센서가 실측이라는 뜻입니다. 출력 모델은 독립적으로 `kind=demo`입니다. 실측 입력에 임시 모델을 적용한 경우 두 값이 함께 존재하는 것이 맞습니다.

## 10. 이후 학습 모델로 연결

같은 특징으로 학습한 모델이면 평균·스케일·가중치·절편을 교체할 수 있습니다. 특징 수·단위·처리 방법이 바뀌면 특징 추출부와 `feature_schema_id`도 함께 교체합니다.

논문의 다축 모델을 연결하면서 현재 RMS 비율 한 개를 복제해 8칸에 넣지 않습니다. 출력 단위가 N 또는 lb인 학습 모델이면 지정한 단위 변환을 한 번만 적용합니다.

이번 완료 기준은 **현재 센서 입력 → 임시 모델 → kgf 결과 → 저장**입니다. 실제 힘을 검증하는 연구 단계는 이 실행 경로가 만들어진 뒤 이어갑니다.
