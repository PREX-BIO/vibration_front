# 04. 집게힘 숫자 출력의 완료 기준

## 1. 이번 완료 상태

아이폰에서 측정이 끝나면 **세 번의 집게힘 데모값과 대표 kgf**를 볼 수 있어야 합니다. 원본 센서 그래프만 나오는 상태는 이번 작업의 완료가 아닙니다.

| 단계 | 확인 |
|---|---|
| 기존 기능 | iPhone Expo Go에서 현재 프로토콜이 그대로 동작 |
| 임시 모델 | 계수 설정을 읽고 비율에서 kgf 계산 |
| 실시간 출력 | 유효한 비율이 들어오면 같은 함수로 kgf 갱신 |
| 결과 출력 | 세 구간 결과와 중앙값 표시 |
| 공유 | 적용한 모델 설정과 kgf가 JSON에 함께 저장 |
| 출처 표시 | 화면·파일에 `demo` 또는 `데모값` 유지 |

## 2. 수학적 테스트

기본 모델은 `clamp(1+5×(r−1),0,15)`입니다.

| 입력 r | 범위 처리 전 | 결과 kgf | clamped |
|---:|---:|---:|---|
| 0.5 | −1.5 | 0.0 | true |
| 1.0 | 1.0 | 1.0 | false |
| 1.6 | 4.0 | 4.0 | false |
| 2.0 | 6.0 | 6.0 | false |
| 4.0 | 16.0 | 15.0 | true |
| null·NaN | 계산하지 않음 | null | false |

부동소수점 비교 허용오차는 절대값 1e-9로 둡니다.

추가 확인:

- 특징 차원·순서와 모델 설정이 맞아야 합니다.
- 표준화 분모가 0 이하이면 모델 로드를 실패 처리합니다.
- 누락 입력을 0으로 대입하지 않습니다.
- 소수점 반올림은 화면에서만 합니다.
- `weak_motor_response` 메모가 있어도 유효한 비율의 **데모 계산**은 수행합니다.
- 원본·모델 스냅샷으로 재계산한 값이 파일의 출력과 일치해야 합니다.

## 3. 사용자가 공유한 기록의 기대 결과

대상: `pinch_20261118T035925274Z_le1zl-0dn72y.json`

| 반복 | 입력 pinch_ratio | 정확한 데모 kgf | 화면 |
|---|---:|---:|---:|
| 1 | 1.5524433593195541 | 3.7622167965977704 | 3.8 |
| 2 | 2.446471026886621 | 8.232355134433107 | 8.2 |
| 3 | 1.6229344556597134 | 4.114672278298567 | 4.1 |

대표값은 `4.114672278298567 kgf`, 화면은 `4.1 kgf`입니다. 이 표는 **기존 센서 특징에 임시 모델을 사후 적용한 계산 예시**입니다. 사용자의 실제 집게힘을 검증한 결과는 아닙니다.

현재 기록의 `median_trial_delta=0.552443…`를 모델의 `r` 자리에 넣으면 안 됩니다. 모델 입력은 각 반복의 `pinch_ratio`입니다.

## 4. 실기기 확인

| 확인 | 기대 |
|---|---|
| 가볍게 접촉 | 기준 수집 후 데모값 생성 |
| 집기·완화 | 실제 센서 특징에 따라 숫자가 변화 |
| 중단·앱 이탈 | 진동·수집 종료, 확보한 데이터 보존 |
| 결과 | 세 구간과 대표값 표시 |
| JSON 공유 | 모델 ID·계수·입력·kgf 결과 포함 |
| 반복 실행 | 이전 기준값과 모델 상태가 새 세션에 섞이지 않음 |

임시 모델이므로 값의 크기가 실제 힘과 같아야 한다는 합격 조건은 두지 않습니다. 확인 대상은 입력과 계산·표시·저장의 연결입니다.
