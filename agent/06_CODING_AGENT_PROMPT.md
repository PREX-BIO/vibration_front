# 06. 코딩 에이전트 전달 지시문

아래 지시문과 이 폴더 전체를 함께 전달합니다.

---

React Native + Expo + TypeScript 기반의 가벼운 **집기 반응 데모**를 구현해 주세요.

사용자는 단단한 책상에 휴대폰을 화면이 위를 향하도록 놓고, 오른손 엄지와 검지로 좌우 긴 변의 중앙을 집습니다. 앱에서 진동을 주며 센서 신호를 기록하고, 집기와 힘을 낮추는 동작에 따른 변화를 그래프로 보여주는 것이 목적입니다.

먼저 `00_README.md`부터 `04_ACCEPTANCE.md`까지 읽고, 근거·제약은 `05_APPENDIX_AND_REFERENCES.md`를 참고해 주세요. 시간표는 01, 계산·필드는 03을 기준으로 구현합니다.

## 확정 범위

| 항목 | 구현 |
|---|---|
| 앱 | Expo + React Native + TypeScript |
| 실행 우선 | Android 실기기 Expo Go |
| 자세 | 책상 위 엄지–검지 한 가지 |
| 수집 | `expo-sensors` 가속도계, 요청 간격 10 ms |
| 진동 | React Native `Vibration`, Android의 시간 지정 |
| UI | 준비 / 측정 / 결과 |
| 계산 | 500 ms 창 RMS, 100 ms 간격, 기준 대비 비율 |
| 저장 | 앱 내부 JSON 한 파일 |
| 공유 | `expo-sharing` |
| 범위 이후 | kgf 모델, 서버, 다른 자세, iOS 실측, 고속 주파수 분석 |

## 구현 지시

1. 기존 저장소가 있으면 지침과 Expo SDK를 먼저 확인하고 프로젝트 구조를 따르세요. 새 프로젝트면 간단한 Expo TypeScript 앱으로 시작하세요.
2. 필요한 패키지는 `npx expo install`로 SDK 호환 버전을 설치하세요.
3. 센서와 진동 시험부터 연결한 뒤 시간표, 계산, 그래프, 저장·공유 순서로 구현하세요.
4. 원본은 버퍼에 모으고 UI는 100 ms 간격으로 갱신하세요.
5. 센서 timestamp는 초, 축 값은 g입니다. JS 수신시각도 별도로 보존하세요.
6. 첫 데모는 JS 수신시각으로 구간을 연결합니다. 데이터에 그 방식을 명시하고 두 시계를 직접 빼지 마세요.
7. 진동·센서·타이머는 완료, 중단, 화면 이탈 시 정리하세요. 시작 연타도 방지하세요.
8. 실측 숫자만 그래프에 연결하고, 부족하거나 무효한 구간은 비워 두세요.
9. 첫 결과는 “기준 대비 센서 변동”입니다. kgf·건강 점수·임의 힘 환산을 추가하지 마세요.
10. Expo Go에서 네이티브 구성을 바꿀 필요가 확인되면 그 이유를 설명하고 Expo development build로 이어가세요. 별도 Kotlin 앱으로 전환하지 마세요.
11. 계산·시간표·중단·JSON 왕복을 중심으로 필요한 테스트를 수행하세요.
12. 예시 재생을 만들 경우 화면과 파일 모두 `replay` 출처를 명확히 표시하세요.

## UI 기준

화면은 일반인이 바로 따라 할 수 있게 단순하게 구성합니다. 현재 동작을 가장 크게, 센서 비율과 그래프를 그 아래에 둡니다. 접점 안내는 단순한 벡터 도식으로 작성합니다. 기술적인 진단과 제한은 결과의 상세 영역에 둡니다.

## 완료 보고

실행 방법, 사용 SDK, 수행한 테스트, 실제 시험 환경을 알려 주세요. 실기기 측정을 했다면 그 JSON과 결과 화면을 제공해 주세요. 실기기를 사용할 수 없었다면 자동 검증 완료 범위와 남은 확인 항목을 분리해 적어 주세요.

Expo Go에서 실행 가능한 소스가 첫 산출물입니다. APK나 서버 배포를 필수 작업으로 확대하지 마세요.

사용자가 맡긴 일반적인 구현 선택은 스스로 결정해 진행하세요. 범위가 크게 달라지거나 실측에 꼭 필요한 정보가 실제로 없는 경우에만 그 지점을 구체적으로 알려 주세요.
