## 1. 이번 앱이 답할 질문

**“같은 설정의 연속 진동에서 휴대폰을 집는 정도를 바꾸면, 관측되는 진동·움직임 신호가 기준보다 얼마나 줄거나 늘어나는가?”**

측정 전체를 하나의 시간축에 기록하고, 감소율 그래프의 특정 시점을 선택하면 그 값을 만든 가속도와 같은 시간대의 각속도·측정 상태가 함께 표시되도록 합니다.

| 사용자 요구 | 구현 결과 |
|---|---|
| 구간마다 얼마나 감쇠되는지 보기 | 구간 배경이 표시된 연속 감소율 그래프와 구간별 요약 표 |
| 감소율과 센서값의 관계 이해 | 같은 시간축의 가속도·각속도 그래프, 공통 커서, 계산 설명 카드 |
| 전체 구간 연속 측정 | 시작부터 종료까지 두 센서 리스너 유지, 전환·휴식·진동 꺼짐도 기록 |
| JSON 다운로드 | 원본, 계산값, 기준, 구간, 진동 명령, 설정을 하나의 파일로 저장·공유 |

메인 지표명은 **‘기준 대비 진동 신호 감소율 (%)’**, 바로 아래 설명은 **‘가속도 변동 기준 · 양수는 감소, 음수는 증가’**로 합니다. 여기서 진동 신호는 센서가 관측한 움직임의 변동입니다. 이 지표의 범위와 논문의 감쇠 측정과의 차이는 부록 A에 정리합니다.

## 2. 측정 자세와 힘 안내

### 2.1 자세

1. 단단하고 수평인 책상에 휴대폰 뒷면을 대고, 화면이 위를 보게 놓습니다. 휴대폰 상단은 사용자에게서 먼 쪽입니다.
2. 오른손 엄지를 오른쪽 긴 변 중앙, 검지를 왼쪽 긴 변 중앙에 놓습니다. 화면의 접점 그림도 같은 위치를 표시합니다.
3. 손가락 끝의 살 부분으로 양옆을 서로 마주 보게 조입니다. 휴대폰을 아래로 누르거나 들어 올리는 동작은 하지 않습니다.
4. 나머지 손가락과 손바닥은 휴대폰에 닿지 않게 하고, 전완은 편하게 지지합니다.
5. 한 세션 동안 책상 위치·휴대폰 방향·케이스 상태·접점을 유지합니다.

### 2.2 동작은 네 가지로 고정

| 화면 안내 | 실제 행동 | 안내용 노력 정도 |
|---|---|---|
| **힘 빼고 접촉만 유지** | 손가락은 같은 위치에 두고 의도적으로 조이는 힘을 풉니다. | 접촉을 유지하는 최소한의 힘 |
| **약하게 집고 유지** | 힘을 조금 주어 조인 뒤, 그 정도를 유지합니다. | 스스로 느끼는 노력 2/10 정도 |
| **중간으로 집고 유지** | 앞보다 분명하게 힘을 높인 뒤 유지합니다. | 노력 4/10 정도 |
| **더 세게 집고 유지** | 중간보다 힘을 높이되, 편하게 유지 가능한 범위에서 유지합니다. | 노력 6/10 정도 |

2·4·6은 **동작을 구분하기 위한 주관적 안내값**입니다. 실제 힘, 최대 힘의 20·40·60%, 표준화된 임상 척도로 사용하지 않습니다. 0kgf를 요구하는 구간도 없습니다. 최대한 세게 쥐도록 요구하지 않습니다.

각 5초 구간의 **첫 2초 동안 해당 동작으로 천천히 바꾸고, 나머지 3초는 유지**합니다. 힘을 푸는 구간에서도 손가락을 떼지 않습니다. 준비 화면에서 이 동작을 한 번 설명하고, 측정 중에는 현재 동작과 남은 초를 크게 보여줍니다.

강도는 ‘약함 → 중간 → 더 셈’으로 안내하지만, 관측 감소율이 반드시 그 순서로 증가하도록 계산하거나 보정하지 않습니다.

## 3. 확정 시간표 — 31초 기록, 25초 연속 진동

시작 버튼 후 준비 카운트다운 3초를 제공하고, 끝나는 순간을 기록의 `t=0`으로 합니다. **기록 길이는 31초이며 준비 카운트다운은 별도**입니다. 화면에는 ‘준비 3초’와 ‘측정 31초’를 구분합니다.

| 기록 시간 | 길이 | phase_id | 화면 안내 | 진동 |
|---|---:|---|---|---|
| 0–3초 | 3초 | `off_pre` | 힘 빼고 접촉만 유지 | 꺼짐 |
| 3–8초 | 5초 | `light_ref` | 그대로 유지 · 기준 측정 | 연속 진동 시작 |
| 8–13초 | 5초 | `pinch_low` | 약하게 집고 유지 | 계속 유지 |
| 13–18초 | 5초 | `pinch_medium` | 중간으로 집고 유지 | 계속 유지 |
| 18–23초 | 5초 | `pinch_higher` | 더 세게 집고 유지 | 계속 유지 |
| 23–28초 | 5초 | `light_recovery` | 힘 빼고 접촉만 유지 | 계속 유지 |
| 28–31초 | 3초 | `off_post` | 그대로 유지 · 종료 기록 | 꺼짐 |

시간 구간은 시작 포함·끝 제외입니다. 이번 절차에는 약함과 중간 사이, 중간과 더 셈 사이의 별도 힘 풀기 구간이 없습니다. 힘 풀기는 23–28초에 한 번 있습니다. 논문의 원문 시간표가 아니라 이번 아이폰 데모를 위한 설계입니다.

### 3.1 시간 설정 객체

아래를 한 곳에 선언하고 UI·수집·진동·분석·내보내기에서 함께 사용합니다.

```json
{
  "protocol_version": "expo_desk_pinch_continuous_31s_v1",
  "countdown_ms": 3000,
  "recording_duration_ms": 31000,
  "vibration_start_ms": 3000,
  "vibration_duration_ms": 25000,
  "vibration_end_ms": 28000,
  "vibration_mode": "ios_core_haptics_continuous",
  "haptic_intensity": 0.5,
  "haptic_sharpness": 0.5,
  "phases": [
    {"id": "off_pre", "start_ms": 0, "end_ms": 3000},
    {"id": "light_ref", "start_ms": 3000, "end_ms": 8000},
    {"id": "pinch_low", "start_ms": 8000, "end_ms": 13000},
    {"id": "pinch_medium", "start_ms": 13000, "end_ms": 18000},
    {"id": "pinch_higher", "start_ms": 18000, "end_ms": 23000},
    {"id": "light_recovery", "start_ms": 23000, "end_ms": 28000},
    {"id": "off_post", "start_ms": 28000, "end_ms": 31000}
  ]
}
```

0.5의 intensity·sharpness는 첫 구현의 고정 설정입니다. 물리적인 힘이나 Hz 값이 아닙니다. 한 세션 중 변경하지 않으며 이후 설정을 바꾸면 설정 ID와 저장값을 갱신합니다.

### 3.2 진동 구현

- 기존 Expo 프로젝트에 Core Haptics를 호출하는 iOS 로컬 네이티브 모듈을 추가하고 **개발 빌드**로 실행합니다.[^development][^modules]
- `CHHapticEvent`의 `hapticContinuous`를 **duration=25.0초인 단일 이벤트**로 만듭니다. 연속 이벤트의 최대 길이는 30초입니다.[^continuous]
- 3초 시점에 재생을 시작하고 28초 시점에 종료되도록 합니다. 구간 변경 때 이벤트를 재시작하지 않습니다. 짧은 햅틱을 반복 호출해 연속처럼 보이게 만들지 않습니다.
- 엔진 생성·준비는 측정 시작 전에 마칩니다. intensity·sharpness는 시작 시 고정하고 시간에 따른 파라미터 변경·추가 오디오·효과음은 넣지 않습니다.
- 로컬 모듈은 지원 여부, 준비, 연속 재생, 정지, 재생 완료·엔진 중단·리셋 통지를 앱에 제공합니다. Core Haptics 미지원이면 이 프로토콜의 시작을 막고 이유를 표시합니다. 기존 펄스 진동으로 자동 대체하지 않습니다.
- 25초 이벤트의 종료는 네이티브 재생 기간으로 제어합니다. JS 타이머가 지연되어도 진동 길이를 늘리지 않습니다. 중단 버튼·앱 이탈 시에는 즉시 정지합니다.
- 시작/정지 요청 시각, 네이티브 재생 예약 시각, 앱에 도착한 응답·완료 이벤트 시각을 구분해 저장합니다. 콜백 도착 시각을 실제 모터의 물리적 시작 시각이라고 기록하지 않습니다.
- 준비가 끝난 하나의 세션 시간축에 진동 예약과 시각 안내를 맞춥니다. 실제 요청·안내가 계획보다 늦으면 그 차이를 기록합니다. 250ms를 넘는 진동 시작/종료 또는 안내 지연은 `timing_mismatch`로 표시하고 정식 구간 비교는 무효 처리합니다. 부분 데이터는 저장합니다. 시간을 맞추려고 진동을 다시 켜지 않습니다.
- 엔진 중단·리셋·재생 오류가 발생하면 세션을 `aborted`로 종료하고 원본을 저장합니다. 그 세션 안에서 자동 재시작하지 않습니다.

### 3.3 기록과 사용자 안내

두 센서 리스너는 `t=0`부터 31초 종료까지 유지합니다. 상태 전환 때 버퍼를 비우지 않습니다. 약함·중간·더 셈·힘 풀기는 각 5초 구간의 처음 2초에 동작을 바꾸고 나머지 3초 유지합니다. 기준 구간의 처음 2초는 진동 안정화 시간으로 제외합니다.

배경·종료 구간은 각각 처음 0.5초만 요약에서 제외합니다. 원본은 제외 없이 모두 저장합니다. 준비 중 자세를 잡고, 측정 중에는 시각 안내만 보여 화면 터치·음성·추가 햅틱이 필요 없게 합니다.

계획 시각과 실제 안내 상태 전환 시각을 모두 저장하고, 구간 요약은 실제 안내 시각과 진동 예약 구간을 함께 확인합니다. 작은 지연은 기록하고, 앞의 `timing_mismatch` 조건을 만족하면 구간 비교를 무효로 둡니다. 실제 기록 종료가 늦어지면 원본을 잘라 버리지 않고 실제 종료 시각까지 보존합니다. 기본 화면 목표와 `planned_duration_ms`는 항상 31000입니다.

## 4. 연속 기록과 시간축

### 4.1 수집할 원본

| 센서/기록 | 값 | 저장 단위 | 역할 |
|---|---|---|---|
| Accelerometer | x, y, z | g | 휴대폰 움직임·진동의 가속도 관측 |
| Gyroscope | x, y, z | rad/s | 회전·비틀림의 각속도 관측 |
| 센서 시각 | timestamp | s | 센서별 실제 표본 간격 확인 |
| 앱 수신 시각 | 세션 시작 대비 수신 시간 | ms | 공통 그래프·구간 배정 |
| 진동 명령 | 연속 진동 시작·종료 요청 | ms | 어떤 구간에 진동을 요청했는지 확인 |
| 구간 이벤트 | 계획 시각·실행 시각·동작 | ms | 안내와 실제 데이터 비교 |

가속도와 각속도는 `expo-sensors`로 수집합니다. 공식 단위는 각각 g, rad/s이며 timestamp는 초입니다.[^accel][^gyro] 두 센서에 업데이트 간격 10ms를 요청하되, 실제 속도는 별도로 계산해 표시합니다. 센서 접근 가능 여부와 권한 결과도 기록합니다.

### 4.2 시간 처리 규칙

- `t_receive_ms = performance.now() - sessionStartMonotonicMs`를 공통 축으로 사용합니다.
- 각 센서의 원래 timestamp를 별도 보존합니다. `Date.now()`는 세션 시작 날짜에만 사용하고 측정 간격 계산에 사용하지 않습니다.
- 가속도와 각속도의 표본을 배열 순서대로 짝짓지 않습니다. 같은 공통 시간창에 들어온 표본들로 각각 계산합니다.
- 같은 그래프 커서는 **같은 수신 시간창**을 가리킵니다. 두 센서가 하드웨어 수준에서 정확히 동시 측정됐다는 뜻으로 설명하지 않습니다.
- 센서 timestamp를 기준으로 실제 Hz를 계산합니다. timestamp가 없거나 잘못된 경우 Hz를 `null`로 두고 수신 기준 Hz를 별도 표시합니다.
- 원본은 배열에 모두 보존합니다. 그래프 렌더링을 위한 표본 축소가 파일 저장 표본을 줄이지 않게 합니다.

## 5. 감소율과 상태량 계산

### 5.1 공통 분석 창

메인 계산은 **최근 2초**, 갱신은 **100ms마다**입니다. 짧은 출렁임을 줄이고 구간을 같은 기준으로 비교하기 위한 창입니다. 진동은 연속이므로 펄스의 켜짐·꺼짐을 평균내는 계산은 사용하지 않습니다. 0.5초 창은 선택 가능한 상세 보기로만 둡니다.

| 설정 | 기본값 |
|---|---:|
| `window_ms` | 2000 |
| `hop_ms` | 100 |
| `phase_settle_ms` | 2000 |
| `off_phase_settle_ms` | 500 |
| `command_late_ms` | 250 |
| `requested_accel_interval_ms` | 10 |
| `requested_gyro_interval_ms` | 10 |
| `min_samples_per_window` | 80 |
| `min_receive_span_ms` | 1800 |
| `max_sensor_gap_ms` | 100 |
| `max_receive_gap_ms` | 250 |
| `min_observed_sensor_hz` | 50 |
| `min_summary_valid_fraction` | 0.80 |
| `numeric_epsilon_g` | 1e-9 |
| `weak_response_ratio_note` | 1.20 |
| `baseline_cv_note` | 0.30 |

이 값들은 분석을 시작하기 위한 개발 설정입니다. 모든 설정을 JSON에 저장합니다. 숫자 변경 시 분석 버전을 갱신합니다.

`t=2000, 2100, …`에서 `[t−2000,t)`의 원본을 계산합니다. 그래프 시각은 창의 끝 `t`입니다. 따라서 ‘20초의 값’은 정확히 한 순간의 값이 아니라 **18–20초의 상태**입니다. 툴팁에 이 범위를 표시합니다. 최초 2초는 원본 그래프만 있고 창 기반 결과는 아직 없습니다.

### 5.2 가속도 변동 크기 A

각 창에서 x·y·z축의 평균을 빼고, 남은 변화량의 RMS를 계산합니다.

\[
A(t)=\sqrt{\frac{1}{N}\sum_i\left[(a_{x,i}-\bar a_x)^2+(a_{y,i}-\bar a_y)^2+(a_{z,i}-\bar a_z)^2\right]}
\]

쉽게 말하면 **‘그 2초 동안 가속도가 평균 주변에서 얼마나 흔들렸는가’**입니다. 축별 RMS도 같은 방법으로 저장합니다. 일정한 중력 성분을 줄이는 계산이며, 손의 움직임이나 자세 변화까지 모두 제거하는 것은 아닙니다. 원본 벡터 크기에서 단순히 1g를 빼지 않습니다.

JSON은 g, 화면은 읽기 편한 mg를 기본으로 사용합니다. `1 g = 1000 mg`입니다. 질량 mg와 혼동하지 않도록 단위 설명에 ‘가속도 단위’라고 표시합니다.

### 5.3 기준 A₀

`light_ref`의 처음 2초를 제외한 **5–8초 안에 완전히 포함되는 유효한 2초 창**의 A 중앙값을 `A₀`로 정합니다. 계획대로 진행하면 창 끝 시각 7.0–8.0초가 해당하며 100ms 간격으로 11개입니다. 기준은 8초에 확정합니다.

- 실제 구간 시작·끝이 다르면 실제 시각으로 동일한 규칙을 적용합니다.
- 기준 구간이 끝나는 시점에 A₀를 확정하고 세션 끝까지 고정합니다.
- 마지막에 힘을 푸는 구간에서도 기준을 바꾸지 않습니다. 그래야 모든 구간을 같은 기준으로 비교할 수 있습니다.
- `A₀ <= numeric_epsilon_g`이거나 요약에 필요한 유효 창이 부족하면 기준은 무효입니다. 작은 값을 임의로 대입하지 않습니다.
- 기준은 접촉 상태의 기준 신호이며, 무접촉 상태나 힘 0의 측정값이 아닙니다.

### 5.4 메인 그래프 D

\[
R(t)=\frac{A(t)}{A_0},\qquad D(t)=100\left(1-R(t)\right)
\]

| 기준 A₀ | 현재 A | D | 화면 해석 |
|---:|---:|---:|---|
| 2.0mg | 1.2mg | +40% | 기준보다 가속도 변동이 40% 감소 |
| 2.0mg | 2.0mg | 0% | 기준과 같음 |
| 2.0mg | 2.6mg | −30% | 기준보다 가속도 변동이 30% 증가 |

예시 숫자는 설명용입니다. `D`를 0–100으로 자르거나 절댓값으로 바꾸지 않습니다. 음수가 나와도 그대로 표시합니다. **음수는 계산 실패가 아니라 관측 신호가 증가했다는 뜻**입니다. 비음수 A와 양수 A₀에서는 이 식의 D가 100을 넘을 수 없지만 음수에는 고정 하한이 없습니다.

저장 필드명은 `accel_reduction_pct`입니다. 물리적 감쇠비를 뜻하는 `damping_ratio`나 힘 단위 `kgf`로 저장하지 않습니다.

### 5.5 각속도 상태량 Ω

\[
\Omega(t)=\sqrt{\frac{1}{N}\sum_i(\omega_{x,i}^2+\omega_{y,i}^2+\omega_{z,i}^2)}
\]

Ω는 해당 창의 **회전 속도 크기**입니다. 일정한 회전도 보이도록 이 값에서는 평균을 빼지 않습니다. 추가로 각 축 평균을 뺀 `gyro_ac_rms_rad_s`도 저장하여 회전 변동을 볼 수 있게 합니다.

각속도는 감소율 계산식에 넣지 않습니다. 감소율이 달라지는 시점에 휴대폰의 회전·비틀림도 함께 달라졌는지 확인하는 보조 관측값입니다. 각속도 하나로 휴대폰 미끄러짐·외부 접촉을 자동 확정하지 않습니다.

### 5.6 진동 꺼짐·기준 확정 전·전환 구간

- **기준 확정 전:** 가속도·각속도는 실시간으로 그립니다. 감소율 자리는 ‘기준 수집 중’으로 표시합니다.
- **기준 확정 후:** 이미 수집한 앞 구간에도 동일 A₀로 D를 계산해 되채웁니다. 최종 파일에는 동일 기준으로 재계산한 전체 곡선을 저장하고 `baseline_available_at_ms`를 남깁니다.
- **진동 꺼짐:** D의 산술 계산은 유지할 수 있지만, 회색선과 ‘진동 꺼짐’ 배경으로 구분합니다. 이를 집어서 줄어든 진동으로 해석하거나 집기 구간 요약에 합치지 않습니다.
- **준비·구간 전환:** 신호와 D를 지우지 않고 점선으로 표시합니다. 창이 구간 경계를 걸치거나 첫 2초를 포함하면 안정 유지 요약에서만 제외합니다.
- **원본 누락:** 해당 센서의 창 결과를 `null`로 표시하고 선을 끊습니다. 마지막 숫자 유지·직선 연결·0 채우기를 하지 않습니다.
- **각속도만 누락:** 가속도가 유효하면 D는 계속 계산합니다. 각속도 영역만 비우고 누락 상태를 표시합니다.

‘전체 구간 연속 측정’은 신호 수집을 끊지 않는다는 뜻입니다. 최초 창 준비, 원본 누락, 기준 부재를 가짜 숫자로 메우라는 뜻은 아닙니다.

## 7. 품질과 누락의 처리

| 상황 | 계산·표시 규칙 |
|---|---|
| 표본 부족, 큰 간격, 비유한 값, 비정상 timestamp | 해당 센서의 창을 무효로 하고 이유 저장 |
| 센서 timestamp 자체가 없음 | 원본·수신 Hz는 보존; 창은 유효성을 보장하지 않고 무효 처리 |
| 기준 가속도 무효 | A·Ω·원본은 표시; D와 감소율 요약은 null |
| 자이로스코프 미지원·권한 없음 | 가속도 측정은 허용; 각속도는 ‘사용 불가’, 0으로 채우지 않음 |
| 앱 배경 전환·사용자 중단 | 센서·진동 정리 후 확보한 부분 기록 저장; 상태는 aborted |
| 진동 시작 실패·엔진 중단·리셋 | aborted로 종료, 확보한 원본과 실패 이벤트 저장 |
| 진동·안내 실행 지연 250ms 초과 | timing_mismatch, 구간 비교 무효, 원본·관측 곡선 보존 |
| 기준이 배경보다 충분히 크지 않음 | D는 계산 가능하면 표시; ‘진동 응답 구분이 약함’ 메모 |
| 기준 구간 변동이 큼 | ‘기준 신호 변동 큼’ 메모; 숫자와 원본 유지 |

각 센서의 창에 대해 표본 수, 수신 범위 길이, native timestamp 단조 증가 여부, 실제 Hz, 최대 native 간격과 수신 간격을 계산하고 5.1의 설정으로 검사합니다. native timestamp가 재시작되면 리셋 이벤트를 남기고 해당 구간의 창을 무효 처리합니다. 임의 보간으로 복구하지 않습니다.

요약은 안정 구간에 예정된 전체 창 중 유효 창 비율이 80% 이상일 때 제공합니다. 가속도와 각속도의 요약 유효성을 각각 판정합니다. 품질 메모는 raw sample이나 계산 가능한 감소율을 삭제하는 조건으로 사용하지 않습니다.

배경 A는 `off_pre`에서 처음 0.5초를 제외한 부분에 완전히 포함되는 유효 창의 중앙값입니다. `off_post`에도 같은 0.5초 규칙을 적용합니다. `A₀ / A_off_pre < 1.2`이면 진동 응답 메모를 남깁니다. 이는 개발용 확인 기준이며 모터 작동 유무나 신호의 원인을 증명하지 않습니다. 배경이 0에 가까우면 비율은 null입니다. `off_post`도 별도 요약하여 처음과 비교하되 배경값을 A에서 임의로 빼지 않습니다.

기준 구간의 CV는 `표준편차 / 평균`입니다. 표준편차는 모집단식 `ddof=0`으로 계산합니다. 0.30 초과 시 메모를 남깁니다. 모든 유효성·품질 설정과 실제 판정 결과를 JSON에 남깁니다.

| `device` | 확인 가능한 기종·OS·Expo·앱 버전, 센서 지원·권한, 알 수 없는 값은 null |
| `setup` | 손·집기 종류·책상 재질·케이스·방향·접점 |
| `config` | 창·간격·제외 시간·검사 임계값·세션 시간표 전체 |
| `vibration` | Core Haptics, continuous 이벤트, duration_s=25, intensity, sharpness, 예약·명령·응답 시각, 완료·중단·리셋 이벤트 |
| `phases` | phase_id, target_level, effort_cue, planned/actual start/end, 요약 대상 범위 |
| `events` | 구간 전환, 진동 명령, 누락·timestamp reset, 앱 이탈·중단 |
| `raw.accelerometer` | 전체 원본 표본 배열 |
| `raw.gyroscope` | 전체 원본 표본 배열 |
| `baseline` | baseline_id, A₀, 기준 원본 범위, 사용 frame ID, available_at_ms, valid, reasons |
| `features` | 동일 시간창의 A, D, Ω, 축별 값, 유효성, 해석 상태 |
| `summary` | 구간별 요약, off 전후, 품질 메모, 누락·기록 통계 |
| `observations` | 사용자가 확인한 이동·추가 접촉 여부; 미응답은 null |

`vibration.hardware_onset_verified`는 별도의 물리적 시작 검증이 없으면 `false`입니다. 네이티브 재생 성공 응답을 물리적 진동 측정으로 바꾸어 기록하지 않습니다. `runtime=development_build`, `planned_duration_ms=31000`, `vibration.duration_s=25`를 저장합니다.

raw 표본은 `sample_id, sensor_timestamp_s, t_receive_ms, x, y, z, phase_id, valid, reasons`를 포함합니다. 센서별 배열과 units를 분리합니다. `phase_id`는 수신 시점의 안내 상태입니다. 비유한 수치는 JSON에 기록할 때 null로 바꾸고 원래 표본의 invalid 이유를 보존합니다.

`features`의 각 frame에는 다음 필드를 포함합니다.

```typescript
type FeatureFrame = {
  frame_id: number;
  window_start_ms: number;
  window_end_ms: number;
  phase_id_at_end: string; // 정확히 경계에서 끝나면 그 경계 직전 상태
  included_phase_ids: string[];
  baseline_id: string | null;
  accel: {
    mean_g: [number, number, number] | null;
    axis_ac_rms_g: [number, number, number] | null;
    ac_rms_g: number | null;
    ratio_to_baseline: number | null;
    reduction_pct: number | null;
    sample_count: number;
    sensor_rate_hz: number | null;
    receive_rate_hz: number | null;
    max_sensor_gap_ms: number | null;
    max_receive_gap_ms: number | null;
    valid: boolean;
    reasons: string[];
  };
  gyro: {
    mean_rad_s: [number, number, number] | null;
    axis_ac_rms_rad_s: [number, number, number] | null;
    ac_rms_rad_s: number | null;
    rms_magnitude_rad_s: number | null;
    sample_count: number;
    sensor_rate_hz: number | null;
    receive_rate_hz: number | null;
    max_sensor_gap_ms: number | null;
    max_receive_gap_ms: number | null;
    valid: boolean;
    reasons: string[];
  };
  reduction_valid: boolean;
  reduction_reasons: string[];
  context: 'motor_off' | 'motor_settle' | 'phase_transition' | 'steady';
  summary_eligible: boolean;
};
```

화면과 파일에서 센서값의 이름과 단위를 일치시킵니다. 중첩 구조의 `accel.reduction_pct`가 본문에서 설명한 `accel_reduction_pct`입니다. `summary_eligible`은 시간상 요약 대상인지 나타내며, 실제 집계에서는 해당 센서의 `valid`도 확인합니다.

`context`의 판정 순서는 다음과 같습니다. 창이 진동 명령의 시작·종료를 걸치면 `phase_transition`, 창 전체가 꺼짐이면 `motor_off`, 전체가 진동 기준 구간의 첫 2초 안이면 `motor_settle`, 동작 경계나 동작 시작 후 첫 2초를 포함하면 `phase_transition`, 나머지는 `steady`입니다. 저장한 실제 시각으로 판정합니다.

### 9.1 구현 순서

1. 프로젝트에서 현재 시간 설정과 진동 호출을 찾고, 3.1의 protocol 객체로 일원화합니다. 화면 문구만 고치지 않습니다.
2. iOS 로컬 Expo 모듈에서 Core Haptics를 연결하고 개발 빌드를 구성합니다. macOS와 Xcode로 로컬 실기기 빌드를 사용할 수 있습니다.[^development][^modules]
3. 첫 확인에서는 손가락 접촉을 유지한 상태로 진동 OFF/ON을 비교합니다. 진동 시작·종료에 따른 관측 신호 변화와 엔진 이벤트를 확인하고 기록합니다. 실제 기기에서 확인하지 않았다면 확인했다고 보고하지 않습니다.
4. 31초 안내, 두 센서 연속 수집, 기준·감소율·상태량 계산을 연결합니다.
5. 전체 그래프와 공통 커서, 구간 요약, JSON 저장·공유·재생을 연결합니다.
6. 아래 시간·계산·실기기 항목으로 검증합니다.

현재 SDK·패키지 관리 방식을 유지하고 필요한 네이티브 기능만 추가합니다. 기존 iOS 수정 사항을 확인하지 않은 채 native 디렉터리를 삭제하거나 전체 프로젝트를 새로 만들지 않습니다. 이번 요구를 Expo Go용 펄스 모드로 대체하지 않습니다.

### 9.2 종료와 구버전

리스너는 자신의 subscription만 제거합니다. 원본 버퍼와 100ms UI 갱신을 분리하고, 종료 때 마지막 완료 창까지 계산한 뒤 기준·요약·파일을 확정합니다. 마지막 불완전한 창은 원본만 보존합니다.

이전 기록은 수정하지 않습니다. 이전 프로토콜 파일은 과거 기록 재생에만 사용하고 신규 측정의 기본값에서 제거합니다. 새 분석을 적용한 재생 결과는 별도 파일로 만들고 `data_origin=replay`, `source_session_id`와 분석 설정을 남깁니다. 과거 파일에 없는 각속도는 복원하지 않습니다.

## 10. 완료 기준과 테스트

### 시간표 일치 테스트

- 준비 카운트다운 3초는 기록 31초와 분리됩니다.
- 7개 phase가 0–31000ms를 빈틈·중복 없이 덮습니다.
- 연속 진동 예약은 3000–28000ms이며 길이는 정확히 25000ms입니다.
- 진행률·완료 타이머·그래프 기본 축·JSON의 계획 길이가 모두 31000ms입니다.
- 정상적인 전체 기록의 2초 창, 100ms hop 결과는 2000–31000ms의 총 291개입니다.
- 기준·집기·힘 풀기의 안정 요약 후보는 각각 11개, OFF 구간은 각각 6개입니다.
- 기준 확정은 8초이며 최초 기준 원본 범위는 5–8초입니다.
- 현재 모드가 `ios_core_haptics_continuous`가 아니면 이 프로토콜로 completed 처리하지 않습니다.

### 계산·데이터 테스트

- A₀=0.002g일 때 A=0.0012g → +40%, A=0.002g → 0%, A=0.0026g → −30%입니다.
- 고정된 가속도 벡터만 들어오면 평균 제거 후 A는 0입니다. 기준도 0이면 D는 null입니다.
- 각속도 (0,0,0.1)rad/s가 일정하면 Ω=0.1, 각속도 AC RMS=0입니다.
- 예를 들어 A의 축별 RMS가 0.003,0.004,0g이면 전체 A는 0.005g입니다.
- 세션 도중 기준을 바꾸지 않으며, 힘 풀기에서 A가 달라져도 메인 기준선은 유지됩니다.
- 구간 경계를 걸치는 창은 그래프에는 남고 안정 구간 요약에는 들어가지 않습니다.
- 실제 안내 이벤트가 늦으면 구간 배정·요약은 실제 시각을 따라야 합니다.
- 가속도와 자이로 표본 수·시각이 달라도 같은 시간창별로 각각 계산됩니다.
- 각속도 누락이 유효 가속도의 감소율을 지우지 않습니다.
- 임의로 만든 데이터는 `synthetic_test`로 표시하며 실제 파일과 섞지 않습니다.
- JSON 원본에서 재계산한 유효 수치가 저장 특징과 절대오차 1e-9 이내로 일치합니다.

### 화면·아이폰 확인

- 측정 중 손가락으로 화면을 조작하지 않아도 단계가 진행됩니다.
- 0초부터 끝까지 가속도·각속도 원본이 기록됩니다. 전환 때 누락을 의도적으로 만들지 않습니다.
- 그래프에서 힘을 푸는 구간·진동 꺼짐·전환 구간을 확인할 수 있습니다.
- 감소율 음수가 보이고, 해당 시점의 A가 기준보다 큰 것을 카드로 확인할 수 있습니다.
- 세 그래프의 커서가 같은 분석 창을 가리킵니다.
- 데이터가 없으면 선이 끊기고 0 또는 이전 값으로 채워지지 않습니다.
- 기준 확정 전에는 기다림 표시, 확정 후에는 이전 데이터의 재계산이 구분됩니다.
- 약함·중간·더 셈의 감소율이 순서대로 나오지 않아도 오류로 판정하거나 값을 고치지 않습니다.
- 측정 완료·중단 모두 JSON을 공유 시트로 내보낼 수 있습니다. 내보낸 파일을 다시 열어 원본과 설정을 확인합니다.
- 결과 화면에 kgf·최대 집게힘·실제 힘 판정이 남아 있지 않습니다.

## 부록 A. ‘감쇠’라는 말과 이번 지표의 범위

이번 변경의 목적은 집는 정도를 바꿀 때 관측 신호가 어떻게 달라지는지 확인하는 것입니다. 이것은 힘으로 환산하기 전에 필요한 단계입니다. 그러나 A는 모터 진동만 추출한 값이 아니므로 **D=40%라는 결과는 ‘가속도 변동 크기가 기준보다 40% 작다’는 뜻**입니다. 기계적 감쇠비 ζ, 감쇠계수, 진동 에너지 흡수율, 자유진동의 지수 감소상수, 집게힘을 뜻하지 않습니다.

‘Smartphone Vibrometric Force Estimation for Grip Related Strength Measurements’에 따르면 연구에서는 힘 센서와 IMU를 동시에 기록하고, 40초 동안 힘 안내를 따라 다양한 힘을 가했습니다. 분석에서는 136Hz 중심·10Hz 폭의 대역을 추출해 신호의 진폭 정보를 사용했습니다.[^vfe] 이 문서의 31초 절차와 2초 RMS는 아이폰 데모용 설계이며 해당 논문의 절차·필터를 재현한 것이 아닙니다.

약 100Hz로 수집한 데이터로 136Hz의 원래 진동을 그대로 분리할 수 없습니다. 약 100Hz의 나이퀴스트 주파수는 약 50Hz입니다. 더 높은 진동이 낮은 주파수처럼 보이거나 장치 내부 처리로 약해질 수 있으므로, 136Hz 필터를 그대로 적용하거나 주파수 해석으로 원인을 단정하지 않습니다.

이번 구현은 Core Haptics의 연속 이벤트를 사용합니다.[^continuous] 같은 제어 설정을 유지하는 것과 휴대폰의 실제 진동 가속도가 일정한 것은 구분합니다. 손으로 잡는 상태·책상 접촉·장치 특성에 따라 실제 관측값은 달라질 수 있습니다. 또한 연속 진동으로 바꿔도 센서 샘플링 속도가 자동으로 높아지지는 않습니다. 이번 감소율은 관측된 가속도 변동의 비교값입니다.

책상에 놓으면 공중에서 지지하는 동작은 줄어들지만, 책상·케이스·카메라 돌출부와의 접촉도 신호에 영향을 줄 수 있습니다. 이번에는 같은 조건을 유지하고 기록합니다. 감소율만으로 손가락의 영향과 책상의 영향을 분리했다고 판단하지 않습니다.

## 부록 B. 결과를 읽는 순서

1. 연속 진동을 실행한 기준 구간이 진동 꺼짐과 구별되는지 봅니다.
2. 집기 구간에서 A와 D가 어떻게 바뀌는지 봅니다. D는 A를 기준과 비교한 값이므로 둘의 관계가 계산과 일치해야 합니다.
3. 같은 시간의 Ω·원본 축·전환 구간을 보며 회전이나 자세 변화가 함께 생겼는지 살펴봅니다.
4. 힘을 풀었을 때 초기 접촉 상태에 가까워지는지 봅니다.
5. 같은 책상·케이스·접점으로 세션을 반복해 변화 양상이 반복되는지 봅니다.

약함·중간·더 셈은 주관적 안내이고 현재 절차는 항상 그 순서로 진행합니다. 따라서 이 한 세션만으로 힘과 신호 사이의 정확한 관계나 시간 경과·피로의 영향을 구분하지 않습니다. 다음 단계에서 실제 힘 센서를 사용하면 같은 시점의 힘을 정답으로 연결할 수 있습니다.
